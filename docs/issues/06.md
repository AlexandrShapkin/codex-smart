# P0: Design safe configuration and migration model

## Context

Thin launcher; minimize cost subject to required correctness and verification.

## Problem and scope

Typed schema, deterministic precedence, preservation, transactional migration and rollback. Treat project config as untrusted.

## Non-goals

No second agent, custom MCP/vector database, hidden installations or unrelated framework.

## Acceptance criteria

CLI wins; unknown fields preserved; dry-run/diff; private backup; atomic apply; rollback; idempotency; symlink and concurrent-edit rejection; preserve Codex MCP/plugins/auth.

## Validation

unit merge tests, migration failure injection and filesystem integration tests
