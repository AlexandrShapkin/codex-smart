# P3: Production hardening and 1.0 readiness

This reference retains #17 history as the final 1.0 readiness umbrella. Dedicated
0.8 hardening execution is #53 and #54; GitHub owns live state.

## Context

Stable means durable public contracts, not feature quantity. Benchmark and Playbooks acceptance are complete; Adaptive Execution is now active while later stages remain planned.

## Problem and scope

Reconcile functional playbooks/adaptive/automation/distribution, independent
security/reliability review, quality evidence and final supported release lifecycle.
Coordinate #55 durable contract and upgrade-path review.

## Non-goals

No second autonomous agent, mandatory Rhai/CodeGraph/Serena/multiple models/subagents
without benefit evidence, fabricated savings, automatic stage advance or implicit
publication. No runtime implementation in this roadmap PR.

## Acceptance criteria

All prerequisite gates accepted. Stable CLI/configuration/migration/workflow schema;
supported Codex/platform compatibility; safe install/update/rollback; quality
benchmark evidence and lifecycle adaptive-policy evidence for any savings claim;
privacy/security review; documented supported matrix, release rehearsal and upgrade
path from supported pre-1.0 versions.

## Validation

Full acceptance matrix; clean install/update/downgrade/rollback/uninstall and release
rehearsal; independent quality/security review and exact-head green CI. Versioning
and actual release authorization remain separate from milestone targets.

## Dependencies

- #13 completed policy evaluation remains historical context, not a requirement to add Rhai.
- #14 benchmark foundation and qualified grading host; #15 separate telemetry/privacy decision.
- #16 distribution/release/migration ownership and #50–#52 completion evidence.
- #40–#42 playbooks; #43–#46 adaptive execution and economics; #47–#49 automation.
- #53 security/supply-chain/privacy and #54 failure recovery/resource/reliability review.
- #55 durable public contract and supported upgrade-path review.

## Known risks

Unmeasured lifecycle costs, unsupported compatibility, security/privacy gaps and
incomplete recovery. Any unresolved acceptance gap blocks stable readiness.
